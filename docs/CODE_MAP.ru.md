# Описание кода: что за что отвечает

Проект `llm-lead-qualifier` — это конвейер, который круглосуточно находит в Instagram людей, принимающих
решения о закупке посуды в ресторанах (шефов, кондитеров, рестораторов, поставщиков), проверяет их и
отдаёт отделу продаж.

## 1. Общая схема

```
Источники ─► Очередь задач ─► Воркеры читают профили ─► Бесплатные правила ─► LLM: текст ─► LLM: сетка ─► Человек ─► Google Таблица
 (sources)      (core/queue)      (ops/workers +              (qualify)        (llm, Haiku)  (llm, Sonnet)  (ops/bot)   (ops/exporter)
                                   access/transport)              │                 │             │
                                                                  └──── все отказы с причиной ──► архивная база
```

Две базы Postgres:
- **основная** (`schema_main.sql`) — прошедшие контакты, реестр заведений, география, роли, настройки,
  вердикты, журнал выгрузок;
- **архивная** (`schema_archive.sql`) — всё служебное и тяжёлое: аккаунты, здоровье эндпоинтов, журнал
  запросов, очередь задач, кэш профилей, отклонённые с причиной, тревоги, журнал вызовов LLM.

## 2. Путь одного профиля

1. **Источник ставит задачу в очередь.** Например, `sources/registry.py` нашёл в 2ГИС ресторан уровня
   PREMIUM с Instagram-аккаунтом и поставил задачу `venue_header` (прочитать шапку заведения).
2. **Воркер берёт задачу.** `ops/workers.py` забирает её через `core/queue.py` (`FOR UPDATE SKIP LOCKED`:
   несколько воркеров никогда не возьмут одну задачу). Аккаунт для запроса выбирает `access/health.py`:
   живой, не на охлаждении, не превысил часовой лимит.
3. **Запрос в Instagram.** Его делает `access/transport/own.py` через личный VPN-выход аккаунта
   (`access/vpn.py`). Удачи и ошибки записываются в здоровье эндпоинта.
4. **Обработчик разбирает ответ.** `qualify/handlers.py` достаёт из шапки заведения упомянутых людей
   («Бренд-шеф @…») и ставит по каждому задачу `profile_info`.
5. **Бесплатные правила.** `qualify/roles.py` ищет должность в шапке, `qualify/rules.py` отсекает аккаунты
   заведений, курсы, кейтеринг и тех, кто сейчас не работает. `qualify/passport.py` проверяет заграницу.
   Отказ уходит в архив через `core/contacts.py`.
6. **Проверка (vet).** `qualify/vetting.py` находит заведение человека и его уровень, проверяет свежесть
   ленты, определяет город и отдел, скачивает 12 превью постов. `qualify/grid.py` склеивает их в одну
   картинку 3×4. Статус становится «сетка_готова».
7. **LLM.** `llm/grader.py` прогоняет текстовую ступень (Haiku, по 25 профилей за вызов), затем ступень со
   зрением (Sonnet, сетка). Уверенные решения применяются, сомнительные помечаются «спорный».
8. **Человек.** `ops/bot.py` присылает спорных карточкой в Telegram. Решение пишется в `verdicts` и
   попадает в следующие промпты как пример.
9. **Выгрузка.** `ops/exporter.py` по команде отбирает готовые контакты с учётом квот отделов,
   `ops/sheet.py` пишет их в Google Таблицу.

## 3. Папки и файлы

### `leadgen/core` — хранилище и обвязка

| Файл | Что делает |
|---|---|
| `db.py` | Подключение к двум базам, применение схем (`init_main`, `init_archive`), объект `Stores` |
| `schema_main.sql` | Таблицы основной базы: `contacts`, `venues`, `geo`, `role_profiles`, `verdicts`, `settings`, `exports` |
| `schema_archive.sql` | Таблицы архива: `accounts`, `endpoint_health`, `request_log`, `work_queue`, `profile_cache`, `rejected`, `alerts`, `grader_log`, журналы источников |
| `queue.py` | Очередь задач: поставить, забрать, завершить, вернуть с ошибкой, подобрать зависшие |
| `contacts.py` | Дедупликация по нику, запись кандидата, отказ с причиной, кэш профиля, перевод в основную базу |
| `settings.py` | Настройки системы в таблице `settings` (лимиты, окна, квоты) |
| `alerts.py` | Запись тревоги, которую бот отправит оператору |
| `venues.py` | Аккаунт и pk заведения в реестре |
| `seed.py` | Разовое наполнение баз накопленными данными (география, заведения, уже сданные ники) |
| `replica.py` | Копия основной базы в Supabase, обновляется по расписанию |
| `backup.py` | Ночной `pg_dump` обеих баз, хранение 14 дней |
| `mirror.py`, `csvfile.py` | Зеркало контактов в CSV для ручной работы |
| `localpg.py` | Локальный Postgres на Mac без Docker |

### `leadgen/access` — доступ к Instagram

| Файл | Что делает |
|---|---|
| `transport/own.py` | Запросы от своего аккаунта (httpx, куки сессии, прокси), разбор страницы профиля и embed |
| `transport/hiker.py` | Альтернативный платный транспорт HikerAPI |
| `transport/__init__.py` | Общий интерфейс транспорта |
| `accounts.py` | Пул аккаунтов: свои, анонимные читатели, прогрев, проверка прокси, оживление упавших |
| `health.py` | Здоровье «аккаунт × эндпоинт»: охлаждение после ошибок, часовой лимит 300 запросов, выбор аккаунта |
| `vpn.py` | Сборка конфига xray: у каждого аккаунта свой SOCKS-порт и свой выход |
| `exits.py` | Какие выходы живы, пересадка аккаунтов с мёртвых выходов (один IP — один аккаунт) |
| `vpn_swap.py` | Новая VPN-подписка из бота: проверить, выбрать режим, применить |
| `account_new.py`, `account_add.py` | Добавление аккаунта: выход, профиль Chrome, ручной вход человеком |

### `leadgen/sources` — источники кандидатов

| Файл | Что делает |
|---|---|
| `registry.py` | Главный источник: обход 2ГИС по городам и рубрикам, заведения с уровнем чека |
| `gis.py` | Разбор выдачи 2ГИС, уровень заведения, поиск Instagram-ссылки на карточке и сайте |
| `gis_cities.py` | Города, слаги 2ГИС, районы, привязка города к отделу (МСК / НСК / СПБ) |
| `afisha.py`, `restoclub.py` | Заведения из каталогов Афиши и Restoclub |
| `websearch.py` | Поиск людей через Brave и DuckDuckGo (`site:instagram.com "шеф-повар" <город>`) и мост «название заведения → аккаунт» |
| `awards.py`, `festivals.py` | Победители премий и спикеры фестивалей |
| `suppliers.py` | Дилеры посуды HoReCa из 2ГИС |
| `expand.py` | Расширение графа: отметки в постах заведений, похожие аккаунты, геометки |
| `rewalk.py` | Повторный обход заведений поглубже |
| `refill.py` | Автоматическое переключение источников, когда очередь пустеет |

### `leadgen/qualify` — отбор

| Файл | Что делает |
|---|---|
| `handlers.py` | Обработчики задач: шапка заведения, подписки, мост, `profile_info` |
| `roles.py` | Каталог ролей как данные (`role_profiles`): маркеры должности, стоп-маркеры, уровни заведений, промпт для LLM |
| `rules.py` | Бесплатные правила: закрытый профиль, аккаунт заведения, стоп-форматы, курсы и кейтеринг, «сейчас не работает» |
| `vetting.py` | Полная проверка кандидата: заведение, уровень, свежесть, город, отдел, превью постов |
| `passport.py` | Паспорт контакта: город из прозы шапки, заграница, дубли одного человека |
| `geo.py` | Поиск города в тексте и определение отдела |
| `geo_points.py` | Город по координатам геометок постов |
| `names.py` | Имя и фамилия из `full_name`, очистка названия заведения |
| `bio_roles.py` | Извлечение упоминаний «должность @ник» из шапки |
| `quality.py` | Проверки моста (имя совпало, категория и город заведения), свежесть, «похоже на человека» |
| `grid.py` | Склейка 12 превью в картинку 3×4 |
| `review.py` | Решения человека по спорным, включение и выключение ролей |

### `leadgen/llm` — оценщик

| Файл | Что делает |
|---|---|
| `grader.py` | Каскад LLM. Текстовая ступень: Haiku, шапка и подписи, `pass / reject / unsure`. Ступень со зрением: Sonnet, сетка и эталоны, вердикт, уверенность, `strong_profile`. Вызов Claude с JSON-схемой, порог уверенности 0,75, few-shot из последних 20 решений человека, дневной лимит вызовов, журнал `grader_log` |

### `leadgen/ops` — эксплуатация

| Файл | Что делает |
|---|---|
| `workers.py` | Пул воркеров и супервизор: какие задачи берёт какой аккаунт, анонимные читатели, перезапуск |
| `bot.py` | Telegram-бот: карточки спорных, тревоги, сводка, команды (выгрузка, роли, VPN) |
| `telegram.py` | Минимальный клиент Telegram Bot API |
| `exporter.py` | Отбор готовых контактов к выгрузке с квотами по отделам |
| `sheet.py` | Запись в Google Таблицу (gspread или Apps Script) |
| `watchdog.py` | Сторож: поток контактов встал → тревога. Утренний отчёт |

### `evals` — оценка качества

| Файл | Что делает |
|---|---|
| `build_gold.py` | Эталон: последнее решение заказчика по каждому нику и вердикты LLM, сделанные до решения человека |
| `predict.py` | Решение правил по одной шапке без сети |
| `metrics.py` | Точность, полнота, F1, интервал Уилсона |
| `run.py` | Боевой отчёт: качество по ступеням, регрессия, экономика каналов, устойчивость аккаунтов |
| `anonymize.py` | Обезличивание шапок для публичных примеров |
| `synthetic.py` | Генератор 330 выдуманных профилей в 22 срезах |
| `offline.py` | Публичный eval: правила, LLM и каскад на синтетике, отчёт в `evals/results/` |

## 4. С чего начать чтение

1. `llm/grader.py` — ядро LLM-части: промпты, схемы, маршрутизация по уверенности.
2. `qualify/rules.py` и `qualify/roles.py` — бесплатная ступень, которая решает 98,4% профилей.
3. `qualify/vetting.py` — полный путь кандидата до сетки.
4. `ops/workers.py` и `core/queue.py` — как устроена параллельная работа.
5. `evals/offline.py` — как измеряется качество.
